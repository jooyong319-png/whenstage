## → `seo.md`

### 목록이 전부 모달이면 상세 페이지가 색인에서 사라진다
캘린더·목록·카드에서 상세를 `<button onClick>`으로 열고 모달만 띄우면, **서버 HTML에 상세
URL이 하나도 안 남는다.** 크롤러는 사이트맵에만 존재하는 URL을 "중요하지 않은 페이지"로
취급해 크롤링을 미룬다(서치 콘솔의 "발견됨 – 현재 색인이 생성되지 않음").

실측 사례: 상세 페이지 34개 중 **11개가 어떤 페이지에서도 링크되지 않는 고아 URL**이었다.

해법 — 링크로 만들고 클릭을 가로챈다. UX는 그대로면서 크롤러·새 탭·가운데 클릭이 다 산다:
```tsx
<a href={detailUrl} onClick={(e) => {
  if (e.metaKey || e.ctrlKey || e.shiftKey || e.altKey) return; // 새 탭은 브라우저에 맡김
  e.preventDefault();
  openModal(id);
}} />
```
CSS는 `text-decoration: none`만 추가하면 기존 버튼 스타일이 그대로 유지된다.
**진단법**: `curl`로 목록 페이지를 받아 상세 URL 패턴이 몇 개 나오는지 세어 보면 즉시 드러난다.

### 저품질 페이지는 noindex와 사이트맵 제외를 반드시 함께
집계 페이지(태그·공연장·아티스트 등)가 항목 1건뿐이면 그 항목 상세와 내용이 사실상 같아
중복으로 남는다. 이때 **상세는 noindex인데 사이트맵엔 올리는 조합이 최악**이다 — 크롤러에
"색인해달라 ↔ 하지 말라"는 모순 신호라 서치 콘솔에 오류로 쌓인다.
→ 판정 함수를 하나 만들어 **페이지 메타데이터와 사이트맵 생성기가 같은 함수를 쓰게** 강제할 것.

임계값은 실측으로 정할 것. "지난 항목만 있는 페이지"만 제외하는 안은 대상이 15건뿐이라
효과가 없었고, 실제 대량 발생 지점은 "항목 1건짜리"였다(해당 사례에서 99개 제외).

### 사이트맵 `lastmod`에 빌드 시각을 넣으면 신호가 죽는다
`lastModified: new Date()`를 쓰면 배포만 해도 전 URL이 "방금 수정됨"이 된다. 한 사례에서
**394개 중 224개가 매번 같은 오늘 날짜**였고, 이런 패턴이 감지되면 구글은 lastmod를 통째로
무시한다. → 실제 콘텐츠 변경일을 쓰고, 모르면 **필드를 아예 생략**한다(약관·소개 페이지 등).

### 구조화 데이터는 "아는 만큼만" — 경고를 없애려고 사실을 만들지 않는다
- **`startDate`에 UTC 오프셋 필수.** `2026-08-07T19:00`처럼 오프셋 없이 내보내면 검색결과에
  시각이 엉뚱하게 뜬다. IANA 타임존이 있으면 **그 날짜 기준** 오프셋을 계산할 것 —
  DST 지역은 계절에 따라 오프셋이 달라 고정값으로는 안 된다:
  ```ts
  new Intl.DateTimeFormat('en-US', { timeZone, timeZoneName: 'longOffset' })
    .formatToParts(probe).find(p => p.type === 'timeZoneName')?.value  // "GMT+09:00"
  ```
  0 오프셋 지역은 `"GMT"`로만 나오니 별도 처리. 구형 런타임 대비 try/catch로 물러날 것.
- **`endDate`**: 하루짜리 행사는 `startDate == endDate`가 구글 권장 방식이다. 시작 시각까지
  아는데 종료 시각을 모르면 **생략**한다 — 임의로 몇 시간 더하면 없는 사실이 나간다.
- **`organizer.url`에 자기 사이트 주소를 넣지 말 것.** 주최사 URL 자리에 우리 페이지를 넣으면
  "주최사 홈페이지가 우리"라는 잘못된 표기다. 빼면 서치 콘솔 경고는 늘지만 정확성이 우선.
- 참고: 서치 콘솔의 **"항목 표시 개선"은 경고이지 오류가 아니다.** 리치 결과 자격은 유지된다.

### `x-default` hreflang은 리다이렉트되지 않는 페이지를 가리켜야
루트(`/`)가 언어별 경로로 307 리다이렉트되는 구조라면 `x-default`를 `/`가 아니라
**기본 언어 페이지**(`/ko` 등)로 지정한다.

### 도메인 이전 — 죽은 도메인을 404로 방치하지 말 것
서비스를 접어도 도메인 이력(백링크·신뢰도)은 자산이다. 배포만 내리면 전 경로가 404가 되고
몇 주 안에 색인에서 털린다. → **구 도메인 → 신 도메인 301 리다이렉트**를 걸고, 서치 콘솔
**주소 변경 도구**까지 실행한다(두 속성이 같은 계정에 있어야 하므로 신 도메인에 구 계정의
인증 태그를 추가로 넣어야 할 수 있다 — 인증 태그는 배열로 여러 개 병기 가능).
- 리다이렉트는 최소 1년 유지해야 정착하므로 **도메인 갱신 기한을 챙길 것.**
- 콘텐츠 주제가 완전히 바뀌었다면 신호가 100% 넘어오진 않는다. 그래도 방치보다 낫다.
- 경로 보존 리다이렉트는 구조가 다르면 404를 양산한다. 루트로 몰아주는 편이 나은 경우가 많다.

### 새 도메인은 그냥 시간이 필요하다
기술적 SEO가 완벽해도 신규 도메인은 색인·순위에 수개월이 걸린다. "노출이 0"인 원인을
기술 문제로 오진하기 전에 **도메인 등록일부터 확인**할 것(RDAP: `https://rdap.verisign.com/com/v1/domain/<도메인>`).
기술 수정은 병목을 제거할 뿐 시계를 앞당기지 못한다.

## → `nextjs.md`

### 클라이언트 컴포넌트의 `usePathname()`은 정적 프리렌더에서도 정상 동작한다
`'use client'` 컴포넌트에서 `usePathname()`으로 로케일을 판별해 URL을 만들어도, SSG 시점에
**빌드되는 라우트의 실제 경로**가 들어온다. `/undefined/...` 같은 게 정적 HTML에 박히지 않는다.
(검증법: 배포본을 `curl`로 받아 로케일별 라벨이 서버 HTML에 이미 찍혀 있는지 확인)

### 데이터 JSON을 스크립트로 수정할 때 라운드트립 먼저 확인
`JSON.parse` → `JSON.stringify(d, null, 2)`가 원본과 바이트 단위로 같은지 **먼저 검증**하면
diff가 깨끗하게 유지된다. 흔한 함정 두 가지:
- 파일 끝에 **개행이 없을 수 있다** → `stringify` 결과에 `\n`을 붙이면 전 파일이 diff에 잡힌다.
- Windows에서 `core.autocrlf=true`면 작업 사본이 CRLF다 → 비교 전에 `.replace(/\r\n/g,"\n")`.

### frontmatter 파서를 직접 만들었다면 CRLF 정규화를 넣을 것
`^---\n ... \n---\n` 정규식은 Windows 체크아웃(CRLF)에서 그냥 실패한다. 파일을 읽은 직후
`.replace(/\r\n/g, "\n")`을 거칠 것. (검증 스크립트도 같은 처리를 해야 헛된 실패를 안 본다)

## → `vercel.md`

### 도메인 리다이렉트는 대시보드 전용 — CLI로 안 된다
`vercel domains`에는 `add`/`remove`/`inspect`만 있고 **redirect 설정 옵션이 없다.**
리다이렉트는 프로젝트 → Domains에서 도메인을 추가한 뒤 **Edit → Redirect to**로 지정한다.
- 최근 UI는 `Settings` 안이 아니라 **프로젝트 상단 `Domains` 탭**에 있다. 계정 레벨
  (`/dashboard/domains`)에도 별도 목록이 있다.
- `Add Domain` 버튼이 안 보이면 대개 **그 도메인이 다른(삭제된) 프로젝트에 아직 물려 있는** 것이다.
  `npx vercel domains inspect <도메인>`으로 어디 붙어 있는지 먼저 확인.
- 검증: `curl -sSI https://old.example.com` → `301` + `Location: https://new.example.com/`

### 배포가 없는 도메인은 404를 반환한다
프로젝트를 지워도 도메인이 계정에 남아 있으면 `X-Vercel-Error: DEPLOYMENT_NOT_FOUND`와 함께
404가 나간다. 서비스 종료 시 리다이렉트를 걸어두지 않으면 이 상태로 방치된다.

## → 새 파일 제안: `web-scraping.md` (또는 `research.md`)

### 검색엔진 요약을 사실로 받지 말 것
검색 결과 요약이 **날짜를 지어낸다.** 실제 사례: 요약이 "7월 29일 공연 시작"이라고 단정했는데
원문을 열어보니 **5월 29~31일** 공연(이미 종료)이었다. "29일"에 엉뚱한 달을 붙인 것이다.
→ 날짜·회장·가격은 **반드시 원문 페이지를 열어** 확인한다. 요약은 후보를 찾는 용도로만.

### 재유통 기사 함정
검색 상위에 **작년 같은 행사** 기사가 그대로 올라온다. 연도가 생략된 공지가 특히 위험하다.
→ 기사의 `article:published_time` 메타태그로 게재 시점을 교차 확인.

### 이미지는 반드시 열어서 눈으로 볼 것 — 치수 검사로는 못 거른다
URL이 200을 주고 크기가 정상이어도 내용이 엉뚱한 경우가 많다. 실제로 걸러낸 것들:
- 밴드 **로고/워드마크**(정상 크기 PNG)
- **행사 포스터**(텍스트가 박힌 세로 이미지 — 치수만 보면 완벽한 인물 사진과 구분 불가)
- 인물이 아주 작게 잡힌 **원거리 무대 컷**
- 31×31px 회색 기본 아바타 (플랫폼이 "없음" 대신 돌려주는 값)

기계적으로 거를 수 있는 것: **가로세로비**. 정사각 카드 썸네일용이면 비율 1.05 초과는
잘려서 못 쓴다. 나머지는 실제로 봐야 한다.

### 기존에 승인된 샘플과 대조해 기준을 잡을 것
품질 기준을 임의로 세우면 이미 통과된 것들과 어긋난다. 기존 데이터에서 몇 개를 열어보고
**실제 눈높이**를 먼저 파악할 것. (예: "스튜디오 사진만"이 아니라 "인물이 프레임을 채우면
라이브 사진도 OK"가 실제 기준이었다)

### Wikimedia 이미지 다루기
- **`/wikipedia/commons/` 경로만 재사용 가능.** `/wikipedia/ko/`, `/wikipedia/en/` 같은 언어판
  자체 저장소는 대부분 비자유(fair-use)라 앨범 커버·로고가 섞여 있다.
- 대표 이미지 조회: `https://en.wikipedia.org/w/api.php?action=query&titles=<제목>&prop=pageimages&piprop=original&format=json&redirects=1`
- **썸네일은 허용된 크기만 된다.** 임의 크기(예: 440px)는 `400 Use thumbnail sizes listed on...`
  으로 거부된다. `250px`/`330px`이 대체로 통하지만 **이미지마다 다르니 실제로 요청해 확인**할 것.
  형식: `.../thumb/<a>/<ab>/<파일명>/330px-<파일명>` (webp·svg 원본은 뒤에 `.png`를 더 붙인다)
- 원본은 10MB PNG 같은 것도 있으니 카드 썸네일엔 반드시 축소본을 쓸 것.
- 연속 요청하면 **429**가 난다. 사이에 텀을 두고, 실패는 재시도할 것(일시적).

### 접근이 막히는 소스는 미리 파악해 대안을 정해둘 것
- 예매/티켓 플랫폼 상세 페이지는 **JS 렌더링**이라 단순 fetch로는 og:image·딥링크가 안 잡힌다
  (공지 목록 페이지는 대개 읽힌다).
- 일부 매체는 봇에 **CAPTCHA 페이지**를 준다. 우회하지 말고 대체 소스를 쓸 것 —
  주 소스가 막히면 그 언어권 수확이 통째로 떨어지므로, 소스 목록 자체를 재검토해야 한다.
- 일부 언론사는 유료화 리다이렉트(`402 Payment Required`)로 넘긴다.

## → `windows-shell.md` (또는 `tooling.md`)

### `perl -CSD`는 스크립트 안의 비ASCII 리터럴을 깨뜨린다
`-CSD`는 입출력을 UTF-8로 디코딩하지만 **스크립트 소스는 바이트로 취급**한다. 그래서
한글·일본어 리터럴로 치환하면 디코딩된 입력과 매칭이 안 돼 **조용히 0건 치환**된다.
→ 비ASCII 치환은 `-CSD` 없이 **바이트 모드**로 돌리거나 스크립트에 `use utf8;`을 넣을 것.
(ASCII만 다루는 치환은 어느 쪽이든 동작해서 눈치채기 어렵다 — 실제로 EN만 성공하고
KO/JA는 조용히 실패한 적 있음)

### PowerShell 5.1에서 네이티브 exe에 `2>&1`을 붙이지 말 것
stderr 각 줄이 ErrorRecord(NativeCommandError)로 감싸지고, exe가 0으로 끝나도 `$?`가
`$false`가 된다. **빌드가 성공했는데 실패로 보인다.** 종료 코드를 정확히 봐야 하면 bash에서
`cmd > log 2>&1; echo $?` 형태로 돌릴 것.

### 동적 정규식은 리터럴 정규식으로 교차 검증
`new RegExp("\\]\\(/" + x + "/...")` 형태가 문자열 이스케이프 단계에서 조용히 깨져 **매치 0건**이
나오는 일이 있다. 0건이 나오면 "문제 없음"으로 오독하기 쉬우니, 리터럴 정규식으로 한 번
대조해 볼 것. 더 나은 방법은 **프로덕션 코드의 정규식을 그대로 복사해** 검증에 쓰는 것이다.
